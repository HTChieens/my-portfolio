Bước Thành phần Nhiệm vụ chính Vì sao cần?
1 Agent Run Agent nhận user request, trigger, schedule hoặc webhook. Xác định mục tiêu hiện tại trước khi lấy memory.
2 Raw Trace Lưu transcript, tool payload, file, approval và provenance. Giữ bằng chứng gốc để audit, debug hoặc rebuild summary.
3 Memory Processing Tóm tắt, rút facts, cập nhật task state. Biến lịch sử dài thành memory dùng lại được.

5 Retrieval + Context Builder Lấy phần liên quan, kiểm tra freshness, nén theo token budget và sắp xếp vào prompt. Giảm cost/latency và tăng quality của context.

1.1 What to remember

Memory type Nhớ gì? Dùng khi nào?
Working memory Vài lượt chat gần nhất, câu hỏi hiện tại, bước agent đang làm. Luôn đưa vào prompt nhưng giới hạn token chặt.
Task state Mục tiêu, bước đã xong, bước còn chờ, blocker, next action. Dùng để agent không quên tiến độ khi workflow chạy dài.
User/entity memory Preference ổn định, thông tin lead/customer/project đã xác nhận. Dùng khi cá nhân hóa hoặc tiếp tục một quan hệ/đối tượng cũ.
Workflow memory Prompt version, enabled tools, output schema, model setting, knowledge source. Dùng khi agent chạy trong một workflow cụ thể trên PAL.
Tool evidence Kết quả tool quan trọng ở dạng digest: conclusion, source id, timestamp. Dùng để ra quyết định mà không nhét raw JSON dài vào context.
RAG/knowledge memory Tài liệu, chính sách, guideline, playbook, FAQ. Dùng khi câu hỏi cần kiến thức ngoài hội thoại.
Audit memory Approval, action log, lý do quyết định, provenance. Dùng khi cần giải thích, rollback, compliance hoặc debug.

1.2 Retrieval architecture

Retrieval method Dùng để lấy Trade-off
Recent turns Mạch hội thoại mới nhất. Rất nhanh, nhưng dễ kéo theo nhiễu nếu thread dài.
Structured lookup Task state, workflow config, user/project/lead theo ID. Chính xác và nhanh, nhưng cần schema tốt.
BM25/keyword Mã đơn, tên riêng, policy code, field name. Tốt với match chính xác, kém với synonym.
Vector search Summary, note, tài liệu dài, nội dung mô tả tự nhiên. Tốt cho semantic recall, nhưng cần filter và rerank.
Rerank Top kết quả có khả năng cạnh tranh. Tăng quality nhưng thêm latency/cost.

1.3 Summarization & compression architecture

Raw events
  -> turn summary
  -> task checkpoint
  -> entity/fact extraction
  -> tool evidence digest
  -> prompt-ready context pack
Tầng nén Đầu ra Điểm cần giữ
Turn summary Tóm tắt mỗi đoạn hội thoại dài. User intent, quyết định mới, câu hỏi còn mở.
Task checkpoint Trạng thái task sau mỗi cột mốc . Goal, done, pending, blocker, next action.
Entity/fact extraction Fact có schema theo user, lead, project, workflow. Source event, timestamp, confidence, sensitivity.
Tool digest Kết luận quan trọng từ tool output lớn. Raw payload id, source system, retrieved_at.

Deliverable 2: Policies

2.1 Remember policy

Nên lưu dài hạn khi Không nên lưu dài hạn khi
Thông tin ảnh hưởng tới quyết định tương lai. Chỉ là câu nói xã giao hoặc cảm xúc nhất thời.
Preference ổn định hoặc được user xác nhận. Dữ liệu nhạy cảm không cần cho nhiệm vụ.
Trạng thái workflow chưa hoàn tất. Raw output quá lớn đã có digest thay thế.
Evidence cho hành động đã thực hiện. Thông tin mâu thuẫn chưa được xác minh.

2.2 Forget policy

Khi nào quên? Cách xử lý Lý do
Task đã hoàn tất. Đóng task state, nén thành final summary, giữ raw trace cho audit. Giảm nhiễu trong prompt tương lai.
Fact có version mới hơn. Mark fact cũ là superseded, ưu tiên fact mới. Chống stale memory.
Dữ liệu nhạy cảm hoặc tạm thời. Không retrieve mặc định, đặt TTL ngắn, mã hóa nếu phải lưu. Giảm rủi ro privacy leakage.
User yêu cầu xóa/quên. Xóa hoặc tombstone theo scope: thread, entity, workspace. User phải kiểm soát được memory.

2.3 Compression policy

  • Không nén mất nguồn: summary phải trỏ về raw event hoặc document version.
  • Không ghi đè raw trace: raw event dùng cho audit; summary chỉ là bản đọc nhanh.
  • Không dùng summary cho quyết định rủi ro cao nếu thiếu confidence: mở lại raw evidence hoặc gọi tool mới.
  • Nén theo milestone: sau khi hoàn thành bước lớn, tạo checkpoint để lượt sau không phải đọc lại toàn bộ transcript.

2.4 Context-rot policy

Vấn đề Policy chống lỗi
Stale facts Fact có freshness score; pricing, promotion, schedule, policy phải có TTL ngắn.
Conflicting facts Nếu hai memory mâu thuẫn, ưu tiên nguồn mới/nguồn hệ thống; nếu vẫn rủi ro thì hỏi user.
Over-retrieval Không lấy thêm chỉ vì còn token budget; dưới relevance threshold thì loại.
Summary drift Summary quan trọng cần định kỳ rebuild từ raw trace hoặc kiểm tra bằng eval.
Wrong scope Memory phải filter theo workspace, agent, workflow, user permission trước khi rerank.

2.5 Cost, quality, latency trade-off

Mode Dùng gì? Cost Latency Quality Khi dùng
Fast Recent turns + task state. Thấp Nhanh Đủ cho task đơn giản Chat thường, hỏi tiếp câu vừa rồi.
Balanced Fast + structured lookup + BM25/vector top-k. Vừa Vừa Tốt Workflow vận hành hằng ngày.
Careful Balanced + rerank + conflict/freshness check. Cao hơn Chậm hơn Cao Gửi email, cập nhật CRM, báo giá, hành động nhạy cảm.
Audit Raw trace + approval log + tool payload. Cao Chậm Cao nhất cho giải thích Debug, rollback, dispute, compliance.

Deliverable 3: Worked Examples

3.1 Sales Agent chăm sóc lead qua nhiều ngày

Lead B2B vào chat ngày thứ Hai, cung cấp ngành nghề, ngân sách, pain point. Thứ Tư quay lại hỏi gói triển khai. Thứ Sáu agent cần tạo proposal.

Giai đoạn Memory cần nhớ Context cần đưa vào prompt Context cần bỏ
Ngày 1: Intake Lead profile, BANT score, pain point, budget, source message. Recent chat + lead fact extraction. Câu xã giao và transcript dài.
Ngày 3: Follow-up Lead summary, objection history, pricing policy hiện tại. Lead summary + policy RAG + CRM stage. Tool raw JSON nếu digest đủ.
Ngày 5: Proposal Package đã chọn, budget đã xác nhận, approval gửi email. Careful mode: facts + evidence + approval requirement. Budget cũ đã bị superseded. 
Prompt context pack trước khi tạo proposal:
Goal: Create proposal for lead L-102.
Task state: BANT completed; package recommended; waiting for send approval.
Lead memory: industry = cosmetics; budget = 2.500 USD setup; pain = slow lead response.
Evidence: CRM digest #crm_883; chat event #msg_172.
Policy: External email requires explicit approval.
Do not use: superseded budget = 1.500 USD from earlier draft.

3.2 Customer Support Agent xử lý ticket dài

Khách mở ticket hoàn tiền. Agent phải nhớ order id, lỗi đã xác minh, chính sách hoàn tiền và quyết định escalation.

Thiết kế đúng Lý do
Lưu order id, purchase date, issue type, refund policy version, escalation owner. Đây là trạng thái nghiệp vụ cần dùng lại.
Ảnh lỗi và raw tool payload lưu object store, prompt chỉ nhận digest. Giảm token và tránh đưa dữ liệu nhạy cảm vào prompt.
Structured order lookup thắng memory chat nếu trạng thái đơn hàng thay đổi. Nguồn hệ thống mới hơn phải có quyền ưu tiên.
Nếu policy version trong summary cũ hơn policy hiện tại, agent phải retrieve policy mới. Chống context-rot do chính sách cũ.

3.3 Workflow Builder Agent nhớ cấu hình project

User xây một agent trên PAL, nhiều phiên sau liên tục chỉnh prompt, thêm knowledge source, đổi model, bật tool. Khi chất lượng agent giảm, hệ thống cần biết thay đổi nào gây regression.

  • Remember: prompt version, model setting, enabled tools, knowledge source ids, output schema.
  • Summarize: mỗi lần publish tạo checkpoint: đổi gì, vì sao đổi, test result trước/sau.
  • Retrieve: khi debug, lấy config diff + eval memory + latest knowledge version.
  • Forget: bản nháp chưa publish không nên ảnh hưởng agent production.
  • Fight context-rot: nếu user hỏi "vì sao agent trả lời khác?", không dùng trí nhớ chung; phải mở config change log.

3.4 Context-rot: Agent nhớ mã giảm giá cũ

User từng dùng mã HE2026 giảm 20%. Một tháng sau policy đổi, mã chỉ còn giảm 10%. Nếu agent retrieve memory cũ mà không kiểm tra freshness, nó sẽ tính sai hóa đơn. 

Luồng đúng:
1. User hỏi: "Áp mã HE2026 cho đơn ORD-101".
2. Retrieval thấy memory cũ: HE2026 = 20%, created_at = 30 ngày trước.
3. Freshness policy phát hiện promotion fact có TTL ngắn.
4. Agent gọi promo/pricing tool hoặc retrieve policy version mới.
5. Tool trả HE2026 = 10%, valid_until = 31/08/2026.
6. Memory cũ được mark superseded.
7. Agent trả lời theo policy mới và có thể nói rõ: "Mã này trước đây từng giảm 20%, hiện tại giảm 10%."
