1. Product Design

PAL Team Workspace là không gian để một tổ chức cùng tạo, thử nghiệm, review và publish agents. Vì agent có thể truy cập dữ liệu, gọi tools và tác động tới workflow thật, workspace cần được thiết kế như một lớp cộng tác có kiểm soát, không chỉ là nơi lưu file.

Information architecture

Organization

Cấp công ty, nơi quản lý security policy, thành viên, groups và quyền mặc định.

Workspace

Không gian theo department hoặc business unit, ví dụ Support, Sales Ops, Internal Tools.

Project

Nhóm agents theo use case, ví dụ Support Automation hoặc Lead Qualification.

Agent

Agent cụ thể gồm canvas flow, prompt, tools, knowledge, guardrails, evals và deployment settings.

Draft / Version

Bản đang edit, bản đang review hoặc bản đang chạy trong staging/production.

Environment

Sandbox, staging và production có quyền tách biệt để tránh thay đổi nhầm môi trường thật.

Workspace dashboard

Dashboard cần giúp user hiểu nhanh agent nào đang chạy, agent nào cần xử lý và team đang thay đổi gì.

Khu vực Nội dung Lý do thiết kế
Agent list Agent name, owner, status, environment, last updated Giúp team scan nhanh tài sản agent đang có.
Review queue Change requests cần review, risk level, required reviewers Biến approval thành một workflow rõ ràng, không phụ thuộc chat rời rạc.
Production health Agent status, recent failures, rollback option Nhắc team rằng agent là hệ thống đang vận hành, không chỉ bản thiết kế.
Recent activity Ai sửa prompt, ai thêm tool, ai approve, ai deploy Tăng accountability trong môi trường nhiều người.

Agent editor no-code

Editor là nơi Builder thiết kế agent và cộng tác với team.

Layout

Left sidebar cho nodes/tools/knowledge/test cases, center canvas cho agent flow, right inspector cho cấu hình node, bottom panel cho test console và eval results.

Top bar

Hiển thị agent name, draft/version, environment, collaborators online, Share và Submit for Review.

Sharing surface

Nút Share trong agent editor cho phép chia sẻ agent với user, group, workspace hoặc guest. Share modal cần hiển thị rõ scope, access level, environment và cảnh báo khi quyền có rủi ro.

Review surface

Review queue và review detail cần cho Reviewer thấy summary, diff, risk level, eval results, comments và các actions: Approve, Request changes, Reject. PAL nên tóm tắt risk bằng ngôn ngữ dễ hiểu để người review không phải đọc cấu hình thô.

Multiplayer layer

Editor cần hỗ trợ presence, cursor/selection trong prompt, node-level editing state, comments và section lock cho các phần nhạy cảm như system instructions, tool permissions, secrets reference và production settings.

2. Permissions & Roles Model

Role mặc định

Role Mục đích Phạm vi
Org Owner Quản lý toàn bộ organization, security policy và quyền cấp cao. Organization
Workspace Admin Quản lý members, groups, projects và workspace settings. Workspace
Project Admin Quản lý project và các agents trong project đó. Project
Agent Owner Sở hữu một agent, quản lý sharing, review policy và version. Agent
Builder Tạo và chỉnh draft agent, chạy test, submit review. Project hoặc Agent
Reviewer Review, comment, approve hoặc request changes. Project hoặc Agent
Operator Deploy, monitor và rollback agent. Environment hoặc Agent
Viewer Xem agent, docs và status nhưng không chỉnh sửa. Workspace, Project hoặc Agent
Guest Cộng tác tạm thời từ vendor/client. Agent, có expiry date

Permission rules

  • Least privilege: user mới chỉ có quyền tối thiểu.
  • Scope-based access: quyền có thể gán ở organization, workspace, project, agent, environment hoặc resource.
  • Environment separation: quyền edit/test ở sandbox không đồng nghĩa với quyền deploy production.
  • Sensitive changes require approval: tool production, secrets, guardrails và deploy cần review theo policy.
  • Explainable access: PAL luôn cho admin biết user có quyền vì role trực tiếp, group hay inheritance.

3. Key Flows

Flow 1: Share agent với user hoặc team

Open Agent → Share → Select User/Group → Choose Access → Confirm
  1. Agent Owner mở agent và bấm Share.
  2. Chọn user, group, workspace hoặc guest.
  3. Chọn access level: View, Comment, Test, Edit Draft, Review, Operate hoặc Admin.
  4. Chọn scope: agent, project hoặc workspace.
  5. Nếu là quyền liên quan tới deploy/test, chọn environment tương ứng.
  6. Nếu là guest, PAL bắt buộc chọn expiry date và khóa quyền xem secrets/production logs.
  7. PAL hiển thị impact summary: người được share sẽ làm được gì, không làm được gì.
  8. Owner xác nhận; PAL ghi audit log.

Flow 2: Multiplayer editing trên agent canvas

Open Shared Draft → See Presence → Edit Nodes → Resolve Conflict → Run Tests
  1. Linh mở Shared Draft và chỉnh node "Refund eligibility".
  2. Minh mở cùng agent, thấy avatar Linh trên node đang edit.
  3. Minh chỉnh test case ở bottom panel; PAL autosave từng object để tránh ghi đè.
  4. Linh chỉnh system instructions; field này bị section lock.
  5. Minh muốn sửa cùng field nên chọn Request control.
  6. Linh release lock hoặc lock tự hết hạn khi inactive.
  7. Cả hai chạy eval suite và xem kết quả chung trong draft.

Flow 3: Submit change for review

Finish Draft → Submit Review → Pre-checks → Assign Reviewers
  1. Builder hoàn tất draft và bấm Submit for Review.
  2. PAL tạo change summary: prompt changes, flow changes, tool changes, knowledge changes.
  3. PAL chạy pre-review checks: missing tests, failed evals, sensitive tool changes, knowledge risk.
  4. PAL xác định risk level: Low, Medium, High hoặc Critical.
  5. PAL đề xuất required reviewers theo policy.
  6. Nếu thiếu test hoặc thiếu reviewer bắt buộc, PAL block submit và nêu lý do.
  7. Builder submit; reviewers nhận notification.

Flow 4: Review, approve và request changes

Open Review → Inspect Diff → Comment → Approve / Request Changes
  1. Reviewer mở Review Queue và chọn change request.
  2. Xem summary, risk level, changed components, diff và eval results.
  3. Comment trực tiếp trên node, prompt section, tool permission hoặc eval result.
  4. Reviewer chọn Approve, Request changes hoặc Reject.
  5. Nếu Request changes, Builder nhận task và cập nhật draft.
  6. Nếu đủ approval theo policy, change request chuyển sang Approved.

Flow 5: Deploy hoặc rollback production

Approved Change → Deploy Checklist → Production → Rollback if Needed
  1. Operator mở approved change request và chọn Deploy.
  2. PAL kiểm tra approvals, evals, tool credentials, rate limits và rollback version.
  3. Operator chọn deploy immediately, schedule deploy hoặc canary rollout.
  4. PAL deploy version mới và ghi audit log.
  5. Nếu production health xấu đi, Operator chọn Rollback.
  6. PAL đề xuất version ổn định gần nhất, yêu cầu lý do rollback và chuyển production về version đó.
