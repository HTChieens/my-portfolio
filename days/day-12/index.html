Scope

Phạm vi bài nộp

Bài nộp tập trung vào luồng cộng tác giữa human và AI agent trên canvas thiết kế. Mục tiêu là làm rõ agent tham gia thế nào, được phép sửa tới đâu, khi nào cần hỏi human và cách tránh làm mất thay đổi của người dùng.

01

Có trong scope

Interaction model, agent nhìn canvas thế nào, conflict/undo, turn-taking và kiến trúc vòng lặp cộng tác.

Không đi sâu

Chưa thiết kế model AI chi tiết, thuật toán layout tự động hoặc code production cho editor thật.

Giả định

Canvas đã có layer tree, object id, selection state và khả năng lưu lịch sử thay đổi theo từng operation.

Cần mentor góp ý

Bản đầu nên để agent chỉ đề xuất hay cho phép chỉnh có duyệt? Conflict nên xử lý bằng operation log đơn giản hay cần CRDT?

Interaction model

Mô hình tương tác human ↔ agent

Hướng đề xuất là canvas-first: agent không chỉ trả lời trong chat, mà có thể hiện đề xuất ngay trên canvas bằng cursor, draft layer hoặc comment. Mọi thay đổi quan trọng vẫn cần human xem trước.

02
Observe

Chỉ quan sát

Agent đọc canvas, selection và lịch sử edit; chưa được tự sửa.

Suggest

Đề xuất

Agent tạo preview hoặc comment. Canvas thật chưa đổi cho đến khi human đồng ý.

Edit with approval

Chỉnh có duyệt

Agent gửi thay đổi kèm lý do và phạm vi ảnh hưởng. Human có thể duyệt một phần hoặc toàn bộ.

Limited auto

Tự chạy có giới hạn

Dành cho việc nhỏ, lặp lại như align hoặc đổi tên layer. Luôn có phạm vi và nút dừng.

Intent Human chọn frame, chat hoặc comment trực tiếp trên object.
Observe Agent nhận scene graph + snapshot + recent ops.
Propose Agent tạo draft layer hoặc nhiều alternative.
Review Human xem diff, lý do, ảnh hưởng và chi phí undo.
Merge Accepted transaction được đưa vào canonical state.
Agent vision

Agent cần đọc dữ liệu gì từ canvas?

Nếu chỉ gửi screenshot thì agent khó chỉnh đúng layer. Vì vậy canvas nên gửi thêm dữ liệu có cấu trúc: layer tree, object id, vùng đang chọn, token thiết kế và các thao tác gần nhất.

03

Scene graph

Frame, layer, kích thước, vị trí, z-index, component và trạng thái auto-layout.

Design tokens

Màu, font, spacing, radius và theme hiện tại để agent không đề xuất lệch style.

Attention scope

Vùng agent đang phân tích: object đang chọn, frame đang mở hoặc nhóm component liên quan.

Recent ops

Một số operation gần nhất giúp agent hiểu human vừa muốn làm gì.

Architecture

Kiến trúc collaboration loop

Đây là kiến trúc ở mức conceptual. Các thành phần chính được tách ra để thấy dữ liệu đi từ canvas sang agent, agent tạo đề xuất, hệ thống kiểm tra quyền và chỉ merge khi thay đổi được duyệt.

04

Human client

Hiển thị canvas, tool, layer đang chọn, comment, proposal và cursor của người tham gia.

Realtime channel

Kênh realtime gửi thay đổi canvas, cursor, selection và trạng thái đang thao tác.

Local undo stack

Cho phép user quay lại thao tác gần nhất, sau đó đồng bộ với lịch sử chung.

Collaboration core
Operation log Lưu thay đổi theo actor, object và thời điểm để có thể undo/merge.
Context builder Gom layer tree, token, selection, comment và ảnh preview cho agent.
Agent planner Đọc ngữ cảnh, hiểu yêu cầu và sinh đề xuất chỉnh sửa.
Policy gate Kiểm tra agent có được sửa vùng này không và có cần duyệt không.
Transaction merger Áp dụng thay đổi đã được duyệt và tạo điểm undo.

Permission service

Quy định agent được xem, đề xuất hoặc sửa vùng nào.

Version store

Lưu snapshot, proposal và lịch sử thay đổi để xem lại.

Notification layer

Báo cho user khi có proposal, conflict hoặc yêu cầu review.

Conflict & undo

Xử lý conflict, undo và lịch sử thay đổi

Nguyên tắc chính: agent không được âm thầm ghi đè phần human đang sửa. Mỗi thay đổi lớn nên có preview, lý do và cách undo.

05
Tình huống Rủi ro UX xử lý Cơ chế kỹ thuật
Human active
Human đang drag object, agent cũng muốn chỉnh spacing.		 Agent ghi đè thao tác trực tiếp. Agent chuyển sang ghost proposal, chờ human thả chuột hoặc dừng thao tác. Activity lock theo selection + debounce idle 700-1200ms.
Agent draft
Agent proposal dựa trên state cũ.		 Proposal không còn khớp canvas hiện tại. Hiển thị “Needs rebase”, cho phép refresh proposal hoặc compare với bản mới. Lưu base_version của proposal và yêu cầu tạo lại proposal nếu state đã đổi nhiều.
Undo
Human muốn undo chỉ phần agent.		 Undo nhầm cả chỉnh sửa của human sau đó. History filter theo actor: All, Human, Agent, Proposal. Nhóm operation theo transaction_id và actor_id.
Partial accept
Human thích layout nhưng không thích màu.		 Accept toàn bộ làm mất kiểm soát chi tiết. Proposal diff tách theo layer/token: accept spacing, reject color. Tách patch theo nhóm: layout, style, text, component props.
Turn-taking

Luật chia lượt giữa human và agent

Trên canvas, human có thể đang kéo, gõ hoặc resize liên tục. Vì vậy agent nên chờ thời điểm phù hợp để đề xuất thay vì chen vào ngay.

06
Idle Không có thao tác hoặc agent đang observe nền.
Human active Pointer down, typing, resizing, dragging, editing text.
Agent thinking Agent phân tích vùng attention, không chạm state chính.
Proposal ready Ghost preview hoặc comment được hiển thị.
Review Human accept, reject, ask why hoặc chỉnh proposal.
Merged Transaction được apply, history tạo undo checkpoint.

Human priority

Khi human đang thao tác trong selection scope, agent chỉ được observe hoặc comment nhẹ. Edit transaction phải chờ idle.

Pause window

Agent có thể đề xuất sau khi human dừng một nhịp ngắn, hoặc khi human gọi trực tiếp: “make this cleaner”.

Stop control

Nút Stop chuyển agent về Observe, hủy background edits chưa merge và giữ lại proposal đã tạo để review sau.

Data model

Ví dụ data model để triển khai

Đây là ví dụ dữ liệu tối thiểu hệ thống nên có. Mục tiêu là biết ai sửa gì, sửa ở đâu, proposal nào được duyệt và undo bằng cách nào.
