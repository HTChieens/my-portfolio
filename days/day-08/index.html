PAL Agent Creation Flow

Redesign flow tạo mới Agent trên PAL

Bài phân tích này tập trung vào flow tạo mới Agent trên PAL. Người dùng muốn tạo một agent mới có knowledge riêng, nhưng flow hiện tại tạo ra nhiều điểm friction: quá nhiều entry point ở màn hình tạo agent, thao tác lặp khi gắn knowledge, và khi upload knowledge thì file bị đưa vào group mặc định tên "New group". Mục tiêu redesign là làm flow rõ hơn, ít friction hơn, và tạo cảm giác tin cậy khi hoàn tất.

Tóm tắt bài nộp
  • Flow được chọn: tạo mới Agent từ màn hình Agents đến bước config, upload knowledge và hoàn tất.
  • Phân tích hiện trạng: chỉ ra friction, confusion và trust issue trong từng bước.
  • Đề xuất redesign: guided setup, auto-attach knowledge, semantic group naming, và summary rõ sau bước knowledge.
Phạm vi flow: Agent - Create New - generate instantly/chat with AI/template - config agent - upload/select knowledge.

1. Bối cảnh & mục tiêu người dùng

Activation flow

Flow tạo mới agent là một thời điểm activation quan trọng. User không chỉ muốn "tạo một item mới"; họ muốn có một agent đủ cấu hình, có knowledge đúng, và có thể dùng hoặc test ngay. Khi flow này gây nhầm lẫn, user dễ tạo agent rỗng, gắn sai knowledge, hoặc mất niềm tin vào trạng thái hoàn tất.

1

Agent

User vào khu vực quản lý agent với ý định tạo agent mới.

2

Create New

Entry point rõ, nhưng sau đó user bị đưa vào quyết định mode.

3

Start mode

Generate instantly, Chat with AI, prompt, chips và templates cùng cạnh tranh chú ý.

4

Config Agent

Màn hình config có nhiều nhóm cài đặt; trạng thái knowledge sau upload chưa được xác nhận rõ trong flow.

5

Knowledge group

Knowledge vừa upload bị gắn vào group tên "New group", dễ trùng và không thể hiện agent owner.

3. Chẩn đoán nguyên nhân gốc

Why it feels bad

Phân nhánh quá sớm

Flow hỏi user chọn cách tạo agent quá sớm. Đây là decision về implementation, trong khi user đang nghĩ theo outcome: agent này làm nhiệm vụ gì?

Context không được giữ lại

Ở bước config, user đang làm việc trong context của agent hiện tại. Tuy nhiên, knowledge được upload trong context này không được tự động attach và không có xác nhận đủ rõ file đã thuộc về agent nào.

Tên mặc định thiếu ngữ nghĩa

Sau khi upload, knowledge được gắn vào group mặc định "New group". Tên này không có ngữ nghĩa, dễ trùng, và làm ownership của knowledge bị mờ ngay từ lúc tạo.

4. Flow redesign đề xuất

End-to-end proposal

Flow hiện tại

  1. Agent
  2. Create New
  3. Choose Generate instantly, Chat with AI, chips, or templates
  4. Config editor starts correctly on System prompt
  5. Go to Knowledge & Memory
  6. Upload knowledge
  7. Tick knowledge again
  8. Knowledge vừa upload được đưa vào "New group"

Flow đề xuất

  1. Agent
  2. Create New
  3. Describe goal as primary path
  4. Configure essentials with visible setup checklist
  5. Add knowledge with auto-attach and clear group name
  6. Show knowledge summary inside the config flow
Agent -> Create New -> Step 1: What should this agent do? -> Step 2: Configure essentials - Show setup checklist: System prompt, Knowledge, Output, Model, Integrations - Keep System prompt as the default start - Surface Knowledge status once files are uploaded or selected -> Step 3: Add knowledge - Uploaded files are auto-attached - Uploaded files go into [Agent name] Knowledge by default - Duplicate names get a clear suffix or rename prompt -> Step 4: Show knowledge summary in config - Attached files - Knowledge group name - Option to remove/rename before updating agent

6. Rationale cho từng thay đổi

Design decisions

Ưu tiên một primary path

Vẫn giữ instant generation, chat-based creation, suggested chips, templates và advanced setup, nhưng không để tất cả cạnh tranh thị giác cùng một lúc. Flow nên dẫn bằng "Describe goal", sau đó đặt templates và advanced setup thành secondary paths để giảm decision fatigue.

Auto-attach knowledge vừa upload

Khi file được upload trong flow tạo agent, default outcome nên là file đó được gắn với agent hiện tại. System prompt vẫn có thể là bước config đầu tiên, nhưng sau khi thêm knowledge, editor cần xác nhận rõ trạng thái attached.

Đặt tên group theo ngữ cảnh

Khi user upload knowledge trong lúc tạo agent, file nên được đưa vào group "[Agent name] Knowledge" thay vì group generic "New group". Nếu tên đã tồn tại, PAL nên thêm suffix rõ ràng hoặc yêu cầu rename trước khi lưu.

Hiển thị summary sau khi gắn knowledge

Không cần thay đổi trạng thái Done nếu bước đó đã rõ. Điểm cần bổ sung là summary ngay trong config: file nào đã attached, thuộc group nào, và có thể remove/rename trước khi update agent.

7. Success metrics

Measurement plan

Time to first usable agent

Đo thời gian trung vị từ lúc bấm Create New đến lần test agent thành công đầu tiên. Kỳ vọng: giảm.

Completion rate

Theo dõi tỷ lệ user hoàn tất tạo agent sau khi đã bắt đầu flow. Kỳ vọng: tăng.

Knowledge attachment accuracy

Theo dõi tỷ lệ agent được tạo với knowledge upload đã attached đúng. Kỳ vọng: tăng.

8. Kết luận gửi mentor

Submission summary
Em chọn flow tạo mới Agent vì đây là một activation moment quan trọng trong PAL. Flow hiện tại đã hỗ trợ nhiều cách bắt đầu như instant generation, chat-based creation, resource mention, suggested chips và templates, nhưng các entry point này đang cạnh tranh sự chú ý trước khi user có đủ clarity. Trong bước config, vấn đề chính nằm ở chỗ knowledge upload trong quá trình setup không được auto-attach, trạng thái attached chưa được xác nhận rõ, và knowledge vừa upload bị đưa vào group mơ hồ tên "New group". Redesign đề xuất chuyển flow thành guided setup, giữ context upload, auto-attach knowledge, tạo group có ý nghĩa theo agent, và hiển thị summary rõ ngay trong config để user biết file nào đang thuộc về agent.
