PAL Tool/Plugin SDK

Thiết kế Tool/Plugin SDK cho MindPal

Bài thiết kế tập trung vào cách developers bên ngoài tạo, kiểm thử và phát hành custom tools cho MindPal mà vẫn bảo vệ agent, workflow và dữ liệu trong workspace.

1. Thiết kế SDK

1.1 Kiến trúc tổng thể

1. Plugin Manifest Developer khai báo tên plugin, tools, auth, quyền và nơi plugin nhận request.
2. Validation MindPal kiểm tra manifest, tool schema, version, domain và quyền.
3. Install Workspace admin chọn plugin, cấp quyền, bật tools cho agent/workflow.
4. Gọi tool Agent hoặc workflow gửi yêu cầu qua cổng gọi tool của MindPal.
5. Result MindPal kiểm tra output, ghi log sự kiện, rồi trả kết quả an toàn cho agent.
Thành phần Vai trò
Plugin Manifest Khai báo plugin là gì, có tools nào, cần auth nào, cần quyền nào, và chạy ở endpoint nào. MindPal sẽ kiểm tra manifest, lưu lại theo version và gắn với domain đã xác minh.
Tool Registry Lưu danh sách tools đã được duyệt trong workspace, tool nào được agent/workflow nào dùng, và version nào đang được chạy.
Cổng gọi tool Nhận yêu cầu từ agent, kiểm tra input, kiểm tra quyền, ký request, gọi plugin và kiểm tra output.
Bộ quản lý auth Quản lý OAuth/API key, lưu secret trong kho mã hóa, hỗ trợ đổi hoặc thu hồi token, và không đưa secret vào prompt hoặc workflow variable.
Bộ kiểm soát quyền Áp dụng quyền tối thiểu, yêu cầu xác nhận với hành động rủi ro, giới hạn dữ liệu, giới hạn số lần gọi, timeout, giới hạn output và nút tắt khẩn cấp.
Developer SDK/CLI Giúp developer tạo plugin, kiểm tra manifest, test cách MindPal gọi tool, phát hành plugin và kiểm tra plugin có tương thích không.

1.2 Tool Schema

{
  "manifest_version": "1.0",
  "sdk_version": "^1.0.0",
  "runtime_protocol": "mindpal.remote_http.v1",
  "id": "com.vendor.plugin",
  "name": "Vendor Plugin",
  "version": "1.0.0",
  "runtime": {
    "type": "remote_http",
    "invoke_url": "https://plugin.vendor.com/mindpal/invoke",
    "health_url": "https://plugin.vendor.com/mindpal/health",
    "timeout_ms": 15000
  },
  "verification": {
    "domain": "vendor.com",
    "public_key_url": "https://plugin.vendor.com/.well-known/plugin-public-key.json",
    "signed_manifest": true
  },
  "auth": [],
  "permissions": [],
  "tools": []
}
Field Mục đích
name Machine-readable tool name, ví dụ create_ticket.
description Model-facing description, giúp agent biết khi nào nên dùng tool.
input_schema JSON Schema cho input. MindPal từ chối tool call nếu input sai schema.
output_schema JSON Schema cho output. MindPal từ chối hoặc làm sạch response nếu output sai schema.
permissions Danh sách quyền tool cần, ví dụ được gọi API nào hoặc được tạo ticket hay không.
risk_level Phân loại rủi ro: read, write, destructive, financial.
confirmation Quy định có cần user approval trước khi gọi tool hay không.
duplicate_protection Cho biết tool có cơ chế chống tạo trùng khi MindPal phải gọi lại request hay không.
data_access Mô tả loại dữ liệu tool cần nhận, ví dụ user_profile, conversation_summary, workflow_input.

1.3 Auth

Khi gọi tool, MindPal chỉ cấp token dùng ngắn hạn hoặc một mã tham chiếu token qua bộ quản lý auth. Plugin không nhận refresh token và không được tự lưu credential lâu dài.

Auth type Khi dùng Cách xử lý
none Public lookup tool, không cần private credential. MindPal vẫn ký request để plugin biết request đến từ MindPal.
api_key Workspace-level integration, ví dụ một API key dùng chung cho team. Admin nhập API key vào MindPal. MindPal mã hóa, hỗ trợ đổi key khi cần, và chỉ dùng key ở phía server.
oauth2 User-specific integration, ví dụ Gmail, HubSpot, Notion, support desk. User authorize qua OAuth popup. MindPal lưu token trong kho mã hóa, chỉ cấp đúng scope đã được duyệt, và cho phép thu hồi theo user/workspace.

1.4 Sandboxing

sandboxing nghĩa là plugin bị cách ly khỏi phần lõi của MindPal. Code của plugin không được truy cập trực tiếp database, memory của agent, kho credential hoặc chi tiết bên trong workflow. MindPal chỉ gửi lượng dữ liệu tối thiểu cần thiết để tool chạy.

Lớp bảo vệ Cách kiểm soát
Cách ly code Plugin chạy ngoài phần lõi của MindPal. Nếu MindPal host plugin, plugin phải chạy trong môi trường riêng và không có quyền đọc file hoặc gọi mạng mặc định.
Giới hạn network Plugin chỉ được gọi qua endpoint đã khai báo, domain đã xác minh, dùng HTTPS và request có chữ ký.
Giới hạn dữ liệu Plugin chỉ nhận input của tool, một ít thông tin về lần chạy, các trường đã khai báo trong data_access, và auth đã được duyệt.
Giới hạn khi chạy MindPal giới hạn thời gian chạy, số lần thử lại, kích thước input/output, số lần gọi và số request chạy cùng lúc.
Kiểm tra output Output của plugin phải đúng output_schema, được làm sạch, xóa secret nếu có và giới hạn độ dài trước khi trả về agent.

1.5 Versioning

versioning cần tách rõ giữa manifest, SDK, plugin release, tool schema và cách gọi tool. MindPal nên khóa version đã được admin duyệt, chỉ tự động nhận update nhỏ không làm đổi hành vi, và yêu cầu duyệt lại nếu plugin đổi quyền, scope, mức rủi ro hoặc input/output schema.

Version field Ý nghĩa
manifest_version Version của manifest format. Thay đổi khi cấu trúc manifest thay đổi.
sdk_version Version range của SDK mà plugin tương thích, ví dụ ^1.0.0.
plugin.version Version release của plugin do developer publish.
tool.version Version riêng cho từng tool. Nếu đổi input/output schema theo cách có thể làm tool cũ hỏng thì tăng version lớn.
runtime_protocol Version của cách MindPal gửi request sang plugin, ký request và trả lỗi.
Rule Cách áp dụng
Tương thích ngược Update nhỏ không được xóa field, đổi ý nghĩa field hoặc tự mở rộng quyền.
Duyệt lại khi đổi lớn Thay đổi lớn cần version mới và admin approval trước khi agent/workflow dùng bản mới.
Quay lại bản cũ MindPal giữ bản manifest đã cài để quay lại nếu release mới bị lỗi.
Thông báo ngừng hỗ trợ SDK cũ được cảnh báo trong CLI validate trước khi MindPal ngừng hỗ trợ.

1.6 Developer experience

SDK cần giúp developer tự phát hiện lỗi schema, auth, quyền và output format trước khi plugin được cài vào MindPal workspace. 

npm create @mindpal/plugin supportdesk-plugin
cd supportdesk-plugin

mindpal plugin dev
mindpal plugin validate
mindpal plugin test --fixture ./fixtures/create-ticket.json
mindpal plugin publish
CLI command Chức năng
create Tạo project mẫu gồm manifest, handler, fixtures, tests, README.
dev Chạy plugin server local và giả lập cách MindPal gọi tool.
validate Kiểm tra manifest, JSON Schema, quyền, auth config và nhãn rủi ro.
test Chạy thử sample request và kiểm tra output schema.
publish Đăng ký manifest URL, upload thông tin plugin và tạo release được khóa version.

3. Mô hình bảo mật

Mô hình bảo mật của PAL Tool/Plugin SDK dựa trên nguyên tắc: không tin plugin một cách mặc định. Mỗi lần tool được gọi, MindPal phải kiểm tra input, quyền, auth, nơi chạy, output và ghi audit log.

3.1 Security principles

Nguyên tắc Thiết kế
Cấp quyền tối thiểu Plugin và từng tool chỉ được xin đúng quyền cần thiết. Admin có thể bật/tắt từng tool.
Xin phép rõ ràng Màn hình cài đặt hiển thị tool list, scope, mức rủi ro và domain được gọi trước khi admin duyệt.
Không đưa secret vào prompt API key, OAuth token, refresh token không bao giờ đi vào prompt, tool description, workflow variable, hoặc logs thô.
Request có chữ ký Mỗi request từ MindPal sang plugin có thời gian gửi, request ID và chữ ký để plugin biết request là thật.
Xác minh nhà phát hành Plugin manifest gắn với domain đã xác minh và bản phát hành có chữ ký để giảm rủi ro bị thay đổi ngoài ý muốn.
Kiểm tra dữ liệu Input và output đều phải đúng JSON Schema. Sai schema thì từ chối hoặc làm sạch trước khi dùng.
Có audit log Mỗi tool call được ghi lại với người gọi, plugin, tool, mức rủi ro, auth connection, trạng thái và thời gian xử lý.
Nút tắt khẩn cấp MindPal có thể tắt plugin, tắt từng tool, hoặc thu hồi credential ngay khi phát hiện rủi ro.

3.2 Threats and mitigations

Rủi ro Cách giảm rủi ro
Plugin xin quyền quá rộng. Review quyền, bật/tắt từng tool, hiển thị scope rõ ràng và cần admin approval.
Manifest hoặc plugin package bị thay đổi. Dùng domain đã xác minh, lưu bản manifest đã cài, yêu cầu chữ ký của nhà phát hành, khóa version và có thể quay lại bản cũ.
Agent gọi nhầm write/destructive action. Dùng risk_level, yêu cầu user xác nhận, và kiểm tra quyền trước khi gọi tool.
Plugin output chứa prompt injection. Kiểm tra output schema, giới hạn độ dài field, làm sạch kết quả và tách output của tool khỏi chỉ dẫn hệ thống.
Lộ secret hoặc token. Lưu secret trong kho mã hóa, tự động che secret trong log, dùng mã tham chiếu token và cho phép thu hồi token.
Request cũ bị gửi lại để lạm dụng plugin endpoint. Dùng chữ ký request, giới hạn thời gian hợp lệ của request và không xử lý lại request ID đã dùng.
Plugin chậm hoặc lỗi. Kiểm tra tình trạng plugin, đặt timeout, giới hạn số lần thử lại và trả lỗi dễ hiểu cho agent/workflow.
Plugin bị chiếm quyền sau khi đã cài. Tắt plugin khẩn cấp, thu hồi credential, kiểm tra lại domain/chữ ký, xem audit log và quay lại bản manifest an toàn.
Lạm dụng qua public chatbot/workflow. Rate limit theo global, IP, session, user ID, và plugin-level limit.
