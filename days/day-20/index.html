PAL Tool/Plugin SDK

Thiết kế Tool/Plugin SDK cho MindPal

Bài thiết kế tập trung vào cách third-party developers định nghĩa, xác thực, chạy, version, test và publish custom tools cho MindPal mà vẫn giữ được boundary an toàn cho agent, workflow và dữ liệu workspace.

1. SDK Design

PAL Tool/Plugin SDK nên được thiết kế theo hướng schema-first governed tool platform. Plugin có thể là một remote HTTPS service do developer vận hành hoặc một isolated runtime được MindPal quản lý. Trong cả hai trường hợp, MindPal vẫn là policy layer: validate schema, kiểm soát permission, xử lý auth, ký request, giới hạn runtime, quản lý version, và ghi audit log.

1.1 Kiến trúc tổng thể

1. Plugin Manifest Developer khai báo metadata, tools, auth, permissions, runtime endpoint.
2. Validation MindPal kiểm tra manifest, tool schema, version, domain, permission.
3. Install Workspace admin chọn plugin, cấp quyền, bật tools cho agent/workflow.
4. Invocation Agent hoặc workflow gọi tool qua MindPal Invocation Gateway.
5. Result MindPal validate output, log sự kiện, trả kết quả an toàn cho agent.
Thành phần Vai trò
Plugin Manifest Khai báo plugin là gì, có tools nào, cần auth nào, cần permissions nào, chạy ở endpoint nào. Manifest được validate, snapshot theo version, và gắn với verified domain.
Tool Registry Lưu danh sách tools đã được approve trong workspace, mapping tool với agent/workflow được phép dùng, và pin version đang chạy.
Invocation Gateway Nhận tool call từ agent, validate input, kiểm tra permission, ký request, gọi plugin endpoint, enforce idempotency, validate output.
Auth Broker Quản lý OAuth/API key, lưu secret trong vault, hỗ trợ token rotation/revocation, không đưa secret vào prompt hoặc workflow variable.
Policy Engine Áp dụng least privilege, confirmation rule, data access policy, rate limit, timeout, output size limit, và kill switch.
Developer SDK/CLI Giúp developer tạo plugin, validate manifest, test local invocation, publish plugin package, và kiểm tra compatibility.

1.2 Tool Schema

{
  "manifest_version": "1.0",
  "sdk_version": "^1.0.0",
  "runtime_protocol": "mindpal.remote_http.v1",
  "id": "com.vendor.plugin",
  "name": "Vendor Plugin",
  "version": "1.0.0",
  "runtime": {
    "type": "remote_http",
    "invoke_url": "https://plugin.vendor.com/mindpal/invoke",
    "health_url": "https://plugin.vendor.com/mindpal/health",
    "timeout_ms": 15000
  },
  "verification": {
    "domain": "vendor.com",
    "publisher_jwks_url": "https://plugin.vendor.com/.well-known/jwks.json",
    "manifest_signature": "required"
  },
  "auth": [],
  "permissions": [],
  "tools": []
}
Field Mục đích
name Machine-readable tool name, ví dụ create_ticket.
description Model-facing description, giúp agent biết khi nào nên dùng tool.
input_schema JSON Schema cho input. MindPal reject call nếu input sai schema.
output_schema JSON Schema cho output. MindPal reject hoặc sanitize response nếu output sai schema.
permissions Danh sách capability tool cần, ví dụ network:api.vendor.com, tickets.write.
risk_level Phân loại rủi ro: read, write, destructive, financial.
confirmation Quy định có cần user approval trước khi gọi tool hay không.
idempotency Quy định tool có hỗ trợ idempotency key hay không, đặc biệt quan trọng với write action.
data_access Mô tả loại dữ liệu tool cần nhận, ví dụ user_profile, conversation_summary, workflow_input.

1.3 Auth

Khi invoke tool, MindPal chỉ cấp short-lived scoped token hoặc opaque token_ref qua Auth Broker. Plugin không nhận refresh token và không được tự lưu credential lâu dài.

Auth type Khi dùng Cách xử lý
none Public lookup tool, không cần private credential. MindPal vẫn ký request để plugin biết request đến từ MindPal.
api_key Workspace-level integration, ví dụ một API key dùng chung cho team. Admin nhập API key vào MindPal. MindPal encrypt, hỗ trợ rotation, và inject server-side khi invoke.
oauth2 User-specific integration, ví dụ Gmail, HubSpot, Notion, support desk. User authorize qua OAuth popup. MindPal lưu token trong vault, enforce scope binding, refresh token an toàn, và cho phép revoke theo user/workspace.

1.4 Sandboxing

sandboxing dùng nhiều lớp: execution boundary, network boundary, data boundary, runtime boundary, và output boundary. Third-party code không được quyền truy cập trực tiếp vào MindPal database, agent memory, credential vault, hoặc workflow internals. MindPal chỉ gửi payload tối thiểu qua HTTPS hoặc isolated runtime channel đã được policy engine kiểm soát.

Boundary Control
Code boundary Remote plugin chạy ngoài MindPal process. Hosted plugin phải chạy trong isolated container hoặc WASM worker, không có filesystem/network mặc định.
Network boundary Plugin chỉ được invoke qua endpoint đã khai báo, domain đã verify, egress allowlist, TLS bắt buộc, và request signing.
Data boundary Plugin chỉ nhận tool input, run metadata tối thiểu, data fields đã declare trong data_access, và auth reference đã được approve.
Runtime boundary MindPal áp dụng timeout, retry budget, input/output size limit, rate limit, circuit breaker, và concurrency limit.
Output boundary Plugin output phải match output_schema, được sanitize, redact secret, và giới hạn field length trước khi trả về agent.

1.5 Versioning

versioning phải tách rõ giữa manifest, SDK, plugin release, tool schema và runtime protocol. MindPal nên pin version đã được admin approve, chỉ tự động nhận non-breaking update, và yêu cầu review lại nếu tool đổi permission, auth scope, risk level hoặc input/output schema theo hướng breaking change.

Version field Ý nghĩa
manifest_version Version của manifest format. Thay đổi khi cấu trúc manifest thay đổi.
sdk_version Version range của SDK mà plugin tương thích, ví dụ ^1.0.0.
plugin.version Version release của plugin do developer publish.
tool.version Version riêng cho từng tool. Nếu đổi input/output schema gây breaking change thì tăng major version.
runtime_protocol Version của invocation envelope, request signing, error format.
Rule Cách áp dụng
Backward compatibility Minor/patch update không được xóa field, đổi meaning của field, hoặc mở rộng permission ngầm.
Explicit upgrade Breaking change cần major version mới và admin approval trước khi agent/workflow dùng bản mới.
Rollback MindPal giữ manifest snapshot theo installed version để rollback khi plugin release lỗi.
Deprecation SDK cũ có deprecation notice trong CLI validate trước khi bị chặn bởi runtime.

1.6 Developer Experience

developer experience của SDK cần giúp developer tự phát hiện lỗi schema, auth, permission, và output format trước khi plugin được cài vào MindPal workspace. 

npm create @mindpal/plugin supportdesk-plugin
cd supportdesk-plugin

mindpal plugin dev
mindpal plugin validate
mindpal plugin test --fixture ./fixtures/create-ticket.json
mindpal plugin publish
CLI command Chức năng
create Tạo project mẫu gồm manifest, handler, fixtures, tests, README.
dev Chạy local plugin server và mock MindPal invocation.
validate Validate manifest, JSON Schema, permission strings, auth config, risk labels.
test Replay sample invocation payload và validate output schema.
publish Register manifest URL, upload package metadata, và tạo release có version pinning.

3. Security Model

Security model của PAL Tool/Plugin SDK dựa trên nguyên tắc: plugin là untrusted by default. MindPal phải kiểm soát input, permission, auth, execution boundary, output, và audit log cho từng tool call.

3.1 Security principles

Principle Thiết kế
Least privilege Plugin và từng tool chỉ được xin đúng permissions cần thiết. Admin có thể enable/disable từng tool.
Explicit consent Install flow hiển thị tool list, scopes, risk level, allowed domains trước khi admin approve.
No prompt secrets API key, OAuth token, refresh token không bao giờ đi vào prompt, tool description, workflow variable, hoặc logs thô.
Signed invocation Mỗi request từ MindPal sang plugin có timestamp, request ID, và HMAC signature để chống giả mạo/replay.
Publisher verification Plugin manifest gắn với verified domain và signed release để giảm rủi ro bị thay đổi package hoặc endpoint ngoài ý muốn.
Schema gate Input và output đều phải match JSON Schema. Sai schema thì reject hoặc sanitize.
Auditability Mỗi tool call được ghi lại với actor, plugin, tool, risk level, auth connection, status, latency.
Kill switch MindPal có thể disable plugin, disable từng tool, hoặc revoke credential ngay khi phát hiện rủi ro.

3.2 Threats and mitigations

Threat Mitigation
Plugin xin quyền quá rộng. Permission review, per-tool enablement, scope labels, admin approval.
Manifest hoặc plugin package bị thay đổi. Verified domain, manifest snapshot, publisher signature, version pinning, và release rollback.
Agent gọi nhầm write/destructive action. risk_level, confirmation rule, policy check trước khi invoke.
Plugin output chứa prompt injection. Output schema validation, field length limit, result sanitization, tool-output isolation.
Credential leak. Vault storage, secret redaction, opaque token reference, token revocation.
Replay attack vào plugin endpoint. HMAC signature, timestamp window, nonce/request ID deduplication.
Plugin chậm hoặc lỗi. Health check, timeout, circuit breaker, bounded retries, graceful error.
Plugin bị compromise sau khi đã install. Kill switch, credential revocation, domain/signature re-check, audit investigation, và rollback về manifest snapshot an toàn.
Lạm dụng qua public chatbot/workflow. Rate limit theo global, IP, session, user ID, và plugin-level limit.
